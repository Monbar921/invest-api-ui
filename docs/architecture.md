# Архитектура invest-api-ui

SPA для [invest-api](../../invest-api/): таблица облигаций с фильтрами и карточка облигации с графиком купонных выплат.

Стек: React 19 + TypeScript, Vite, Mantine 9 (`mantine-datatable` - таблица, `@mantine/charts` - график),
TanStack Query - запросы и кэш, React Router - маршруты.

```
браузер ──▶ UI ──(same origin)──▶ invest-gateway ──▶ invest-api
                                       └── Keycloak (логин)
```

## Экраны

- `/` - гостю лендинг (`LandingPage`): что умеет продукт (открытые гостю разделы - ссылками, «Карточка облигации» - на карточку первой облигации примера, портфель и уведомления -
  «после входа»), «Войти / Зарегистрироваться» (вход с возвратом на `/`) и «Смотреть облигации», первые 5 облигаций первой
  подборки (нет подборок или бэк не ответил - блока нет), оговорка «не даёт инвестиционных рекомендаций». Вошедшего `/`
  ведёт на `/bonds`.
- Колокольчик у тикера в таблице и рядом с названием в карточке: залит, если есть включённые уведомления; открывает
  окно с переключателем и числом дней на каждый тип события (купон, частичное погашение, оферта, погашение). Ниже -
  «Цена и доходность»: текущие цена и доходности, пороги текстом («Цена ≤ 95% номинала») с переключателем и удалением,
  форма добавления: тип (уровень цены, изменение от текущей, изменение за день, доходность к погашению или оферте),
  направление и порог. Между ними - «События и новости»: переключатели «Объявлен купон», «Новости», «Рейтинги эмитента».
  Выключение не удаляет правило. Если Telegram не подключён - предупреждение. Все правила пользователя - одним
  запросом на всю таблицу.
- `/alerts` «Уведомления» (пункт в шапке): карточка «Банк России» с переключателем решений по ключевой ставке, облигации - кратко: правила бейджами (выключенные - с пометкой), «Настроить» открывает то же окно, что колокольчик, удаление всех правил облигации - с подтверждением; правила по облигациям карточками (удалить все по облигации) и история
  отправленного со статусом и ошибкой, «Показать ещё».
- Шапка: кнопка Telegram открывает панель уведомлений - статус (подключён ли, с какого времени, отвечает ли Telegram
  серверу), «Подключить Telegram» выдаёт одноразовую ссылку на бота на 10 минут (кнопки `tg://resolve` - сразу в приложение - и `t.me`, плюс код для отправки боту вручную, если Telegram потерял параметр `start`) и ждёт, пока в боте нажмут «Старт»
  (опрос раз в 3 секунды), «Отключить». Если бот выключен на сервере - только сообщение об этом.
- `/bonds` - слева лента: ключевая ставка ЦБ (с какого дня, изменение с начала года и на последнем заседании), курсы USD / EUR / CNY с изменением, новости
  Банка России, Мосбиржи, рейтинговых агентств (АКРА, НКР - только дата, без времени) и СМИ с фильтром «Все / ЦБ /
  Биржа / Рейтинги / СМИ» и кнопкой «Показать ещё»; у новости - источник, время,
  заголовок-ссылка на источник, анонс, облигации (ссылки на карточки) и эмитенты. На экране уже `lg` лента уходит под
  таблицу. Страница шире остальных (контейнер до 1920 px вместо `xl`), лента занимает 7/24 ширины, с `xl` - 6/24;
  колонка «Риск» - фиксированной ширины, чтобы бейдж не обрезался. Справа - облигации: поиск облигации по мере ввода (тикер, ISIN, название, тот же компонент `BondSearch`, что в
  калькуляторе) - ищет по всем облигациям, а не по текущей выборке, выбранная открывается в карточке; вкладки «Все / Рублёвые / Валютные» (`all` / `local` / `foreign` на бэке), фильтры по цене
  в рублях и в % от номинала, риску, ОФЗ и типу купона (постоянный / переменный), сортировка по колонкам, серверная пагинация. Колонка «Купон, % к цене» - купонная доходность (сумма купонов за год к текущей цене, не ставка от номинала), под ней тип купона (постоянный / переменный) и число выплат в год. Колонки
  «К погашению, % год.» (сортировка `YIELD_TO_MATURITY`) и «К оферте, % год.» (сортировка `YIELD_TO_OFFER`,
  под значением дата оферты); «—», если оферты нет или бэк не смог посчитать доходность (например, флоатер).
- `/portfolio` «Портфель» (пункт в шапке): первой карточкой - весь портфель в рублях (если у всех валют есть курс), дальше итоги по валютам номинала (текущая стоимость, сумма покупки, доход в
  деньгах и %), таблица - строка на облигацию: все её покупки сведены (количество, средняя цена, суммы; «N брокера» с именами в подсказке, диапазон дат), стрелка раскрывает покупки (у них «изменить» / «удалить» и заплаченные рубли), «+» - новая покупка этой облигации; облигация с одной покупкой - строка и есть покупка (действия в ней, стрелки нет). Кнопки и названия стоят ровными колонками: на месте отсутствующих - пустое место той же ширины. Колонки: облигация (ссылка на карточку), брокер, дата, количество, купон (% от номинала), доходность к погашению по цене покупки (под ней - «сейчас», по текущей цене), цена покупки и текущая в % от
  номинала, стоимость и доход (у валютных - подписью в рублях: стоимость по курсу на сегодня, доход - с учётом курса на дату покупки), доход в % (прибыль зелёная, убыток красный), брокер. «Добавить покупку» - окно с поиском
  облигации, количеством, ценой (по умолчанию - текущая цена облигации), датой (не позже сегодня), брокером (выпадающий список своих брокеров; новый - ввести имя и «+ Добавить», дальше он есть в списке) и у валютной облигации - «Заплачено, ₽» (необязательно, без НКД и комиссии; видно под ценой покупки); в строке -
  изменить (без смены облигации) и удалить с подтверждением. Доход в колонке «Доход от цены» - только от изменения
  цены непроданных облигаций. В форме покупки - необязательные НКД и комиссия (пусто - НКД по графику купонов,
  комиссия 0).
  Полный доход ([INVEST-001-portfolio-income](../../invest-api/docs/features/INVEST-001-portfolio-income/)):
  переключатель «Без НДФЛ / НДФЛ 13 % / НДФЛ 15 %» (по умолчанию 13 %, ставка уходит в `taxRatePercent`; прежние
  цифры видны, пока считаются новые), первой карточкой - «Полный доход, в рублях» с XIRR и разбивкой (доход от цены,
  купоны, НКД, комиссии, НДФЛ; сколько вернулось амортизацией), в таблице - колонки «Полный доход» (под суммой - % к
  вложенному, разбивка в подсказке) и «XIRR»; неполный итог - оранжевая «*» с причиной в подсказке. Кнопка «Продать»
  в строке облигации - окно продажи: количество (по умолчанию всё непроданное, подсказка «В портфеле N шт.»), цена
  (по умолчанию текущая; выкуп по оферте - 100), дата, необязательные НКД и комиссия, брокер; ошибку `422` (не
  хватает облигаций) показывает текст бэка и убирает его, как только поле изменили. Частично проданная покупка - «3 из 10» в раскрытой строке. Под таблицей -
  «Закрытые позиции» (проданные и погашенные целиком: куплено, даты, полный доход, XIRR); портфель только из закрытых
  позиций не считается пустым. Удаление покупки, которое оставило бы продажу без облигаций, показывает ошибку бэка.
  Вкладки «Покупки», «Сделки», «Выплаты» и «Импорт» (вкладка в адресе: `/portfolio?tab=trades`, `/portfolio?tab=payments`,
  `/portfolio?tab=import`).
  «Сделки» (`PortfolioTrades`): покупки, продажи и погашения новые первыми - дата, вид, облигация, количество, цена,
  сумма, НКД («по графику», если не вводили), комиссия, брокер; у продаж - изменить и удалить с подтверждением;
  «Добавить продажу» - то же окно с выбором из облигаций портфеля (продать можно только купленное). Цены сделок - до
  4 знаков (`formatPricePercent`). XIRR - для позиций от 30 дней (бэк), у моложе - «—». «Выплаты» (`PortfolioPayments`,
  [INVEST-001-payment-calendar](../../invest-api/docs/features/INVEST-001-payment-calendar/)): период 3 мес / 6 мес /
  год / 3 года, итог за период в рублях и по валютам («от …», если размер части выплат не объявлен, и
  предупреждение), столбики сумм по месяцам в рублях (месяц с необъявленными выплатами - «*»), таблица событий по
  месяцам: дата, тип, облигация (ссылка на карточку), количество, на облигацию (прошлый размер купона, если
  изменился), сумма (у валютных - в рублях); у оферты и погашения с остатком в амортизации - «—» с подсказкой.
  Блок «Подписка в календаре»: «Создать ссылку» - адрес `<origin>/api/calendar/<токен>.ics` показывается один раз
  с кнопкой копирования; потом - когда создана, «Новая ссылка» и «Отключить ссылку» с подтверждением на месте.
  «Импорт» (`PortfolioImport`, [INVEST-001-broker-import](../../invest-api/docs/features/INVEST-001-broker-import/)):
  мастер «Источник → Предпросмотр → Отчёт» (Stepper). Источник - «Т-Инвестиции по токену» (подсказка, где создать токен
  «Только для чтения», поле пароля; после подключения - «Токен …XYZ9», выбор счетов, «С даты», «Загрузить сделки»,
  «Отключить токен»; токен в UI нигде не хранится и после отправки стирается из поля) или «Файл отчёта» (формат CSV, отчёт
  Сбербанка или Альфа-Банка с описанием, `FileInput`; отправка - `FormData`, `request` не ставит ему `Content-Type`).
  В обоих источниках - «Брокер» (`BrokerSelect`): по умолчанию брокер источника («Т-Инвестиции», «Сбербанк»,
  «Альфа-Банк», у CSV - пусто, тогда из столбца файла), а если у пользователя уже есть брокер с тем же именем без
  учёта регистра и знаков («АльфаБанк») - он; смена формата сбрасывает брокера и файл. Импорт по токену выключен на
  бэке - сразу «Файл отчёта». Открытый импорт - в адресе (`?tab=import&import=<id>`, `useImport`): шаг мастера
  переживает перерисовку и обновление страницы; отчёт после подтверждения кладётся в кэш сразу.
  Предпросмотр: счётчики по статусам, пропущенные операции, предупреждения, облигации не из системы, таблица с флажками
  (по умолчанию выбраны только «Новая»; «Уже импортирована», «Нет в системе», «Ошибка» выбрать нельзя; НКД и
  комиссия - в валюте номинала; на телефоне у шагов нет описаний, подписан только текущий), «Импортировать выбранные (N)». Отчёт - те же строки
  со статусами и причинами. Ниже - последние импорты списком с «Открыть» (неподтверждённый предпросмотр можно
  подтвердить позже; бэк отдаёт его с актуальными статусами). Нет фичи `BROKER_IMPORT` в тарифе - подсказка «Доступно в
  платном тарифе» и закрытая форма. После подтверждения перечитываются портфель и тариф. Пустой портфель ссылается на
  импорт.
- Числа во всех формах (портфель, калькулятор, фильтры, пороги уведомлений): дробная часть - через запятую или
  точку, в поле показывается запятая; недописанное число («79,») остаётся в поле, наружу уходит уже число.
- `/plan` «Тариф» (кнопка с короной в шапке, только у вошедшего; гостю - «Войти»,
  [INVEST-001-plans](../../invest-api/docs/features/INVEST-001-plans/)): действующий тариф (платный или нет,
  описание), срок («тариф по умолчанию», «по ДД.ММ.ГГГГ включительно» или «бессрочно»), использование лимитов -
  «N из M» с полосой (исчерпан - красным; больше лимита - «созданное раньше сохранено»), таблица сравнения тарифов
  (цена, лимиты и фичи, «ваш» у действующего). Оплата ([INVEST-001-payments](../../invest-api/docs/features/INVEST-001-payments/),
  `components/PlanPayments.tsx`): у тарифа с ценой - «Купить» («Продлить» у действующего); в диалоге - цена и срок,
  что будет с текущим тарифом, автопродление, согласие с офертой и политикой персональных данных (ссылки из
  `payments` ответа тарифа; без галочки кнопка неактивна); «Перейти к оплате» - `POST /api/account/payments` и
  переход на страницу Т-Кассы. Т-Касса возвращает на `/plan?payment=<id>`: баннер «Ждём подтверждение» с опросом
  статуса раз в 3 с (около двух минут), затем «Оплата прошла» или «Оплата не прошла» с причиной (платёж не найден - `404` без повторов запроса, сразу «Платёж
  не найден»); итог перечитывает
  тариф и историю, крестик убирает `payment` из адреса. Автопродление в карточке тарифа: сумма, день списания, карта
  `•••• 0777`, «Отключить автопродление» с подтверждением; без него у оплаченного - когда тариф закончится. «История
  платежей» - дата, тариф и срок (автопродление помечено), сумма, карта, статус; у ждущего оплаты - «Оплатить».
  Оплата выключена на бэке - кнопок нет, «Оплата пока недоступна». Тариф перечитывается после
  создания и удаления правил и покупок. Ответ `402` при создании правила, покупки или ссылки календаря показывается
  сообщением бэка со ссылкой «Тарифы»; если подписки на календарь нет в тарифе, в блоке «Подписка в календаре»
  вместо кнопки - «Доступно в платном тарифе «…»», у созданной раньше ссылки - предупреждение и только «Отключить».
- `/calculator?ticker=` - калькулятор дохода: поиск облигации по мере ввода (тикер, ISIN, название), её цена, купон,
  доходности к погашению и к оферте, сектор; форма с количеством, датами и ценами покупки и продажи и переключателем НДФЛ со ставкой 13 или 15%, ставкой вклада для сравнения (по умолчанию - ключевая ЦБ); результат -
  доход в деньгах и %, % годовых, при включённом налоге - НДФЛ и доход после налога, вклад на ту же сумму (доход, НДФЛ, что выгоднее и на сколько), разбивка по выплатам. Открывается из шапки и из карточки.
- Блок «Купить у брокера» (`BrokerLinks`) - в карточке облигации под показателями и в калькуляторе под расчётом:
  кнопки брокеров-партнёров (ссылка в новой вкладке, `rel="sponsored"`), пометка «Реклама», у каждой ссылки
  рекламодатель и erid, подпись «Это не инвестиционная рекомендация». Партнёров нет или запрос не удался - блока нет.
  Клик параллельно отправляет учёт перехода (`fetch` с `keepalive`), сбой учёта не виден и переходу не мешает
  ([INVEST-001-broker-referral](../../invest-api/docs/features/INVEST-001-broker-referral/)).
- `/issuers/:id` - эмитент (id Мосбиржи): название, полное название, ИНН, выпуски из системы (те же колонки, что в
  списке, без сортировки - по дате погашения) и новости эмитента с «Показать ещё». Открывается из карточки облигации
  («Эмитент: ...»).
- `/collections/:slug` - подборка на готовом фильтре («Самые доходные ОФЗ», «Флоатеры», «Погашение в этом году»):
  заголовок, описание и облигации в порядке бэка, страница - в `?page=`. Ссылки на подборки - над списком облигаций.
- `/bonds/:ticker` - карточка: график цены в % от номинала по дневным свечам (интервалы «Д / Н / Мес», периоды
  «1М / 6М / 1Г / 3Г / Всё»), а также цена, номинал (с отметкой об амортизации), НКД, купон (с типом: постоянный / переменный), доходность к погашению
  (в подсказке - доходность к оферте и дата оферты), погашение, ближайшая выплата и график выплат. Под графиком цены -
  блок с двумя вкладками: «События по бумаге» (купоны с пометкой, если размер вырос или снизился, амортизация,
  оферта, погашение; прошедшие - серым, будущих сначала 8) и «Новости» (сообщения, где упомянут выпуск или его эмитент,
  грузятся при открытии вкладки). События и новости намеренно разделены: первые - из графика выплат, вторые - внешние.

## Метаданные страниц (SEO)

По ссылке страницы облигации, эмитента, подборки и списка приходят от gateway уже с title, description, canonical,
Open Graph и готовым HTML в `#root` ([INVEST-001-seo-pages](../../invest-api/docs/features/INVEST-001-seo-pages/design.md));
React при загрузке заменяет содержимое своим. При переходах внутри SPA те же теги обновляет `usePageMeta`
(`lib/seo.ts`): меняет существующие теги, а не добавляет новые; пока данные грузятся - не трогает; значения нет -
тег удаляется. Title - «<заголовок> - Облигации», canonical - путь без query. Портфель, уведомления и 404 - `noindex`
без canonical. Title и description карточки, эмитента и подборки строятся по тем же правилам, что в gateway
(`SeoPageBuilder`) - менять их нужно в обоих местах.

## Авторизация

Облигации, лента, карточка и калькулятор открыты без входа (публичный режим gateway, [INVEST-001-public-mode](../../invest-api/docs/features/INVEST-001-public-mode/));
портфель и уведомления - только после входа.

- Состояние входа узнаётся до загрузки приложения: обычный скрипт в `index.html` сразу запрашивает `GET /api/session`
  (отвечает сам gateway, всегда `200`: `{authenticated, username}`), `main.tsx` ждёт ответ (`window.investSession`) и
  кладёт его в `SessionContext` (`api/session.ts`, хук `useSession`). За время жизни страницы оно не меняется: вход и
  выход - переходы на Keycloak и обратно. Ответа нет (сеть, gateway недоступны) - приложение рисуется для гостя.
- Гость: в шапке «Войти» вместо кнопки Telegram и выхода; «Портфель» и «Уведомления» показывают `LoginRequired` - что
  здесь будет и «Войти»; колокольчик облигации открывает окно с тем же предложением. Хуки личных данных
  (`useAlerts`, `useNotifications`, `usePortfolio`, `useBrokers`, `useTelegramStatus`) у гостя выключены - он не
  получает `401`.
- Вход - `login()`: `/oauth2/authorization/keycloak?returnTo=<путь и query текущей страницы>`, после входа gateway
  возвращает на ту же страницу.
- Ответ `401` на любой запрос (сессия истекла) - `client.ts` вызывает `login()`.
- Анонимные запросы ограничены по IP (gateway отвечает `429`) - пользователь видит обычную ошибку запроса с текстом
  от gateway.
- Изменяющие запросы (не GET/HEAD/OPTIONS) отправляют значение cookie `XSRF-TOKEN` в заголовке `X-XSRF-TOKEN` - и у
  гостя (POST страницы облигаций и расчёта калькулятора): cookie ставит gateway уже на ответ `/api/session`.
- Выход - `POST /logout`, gateway отвечает `202` с адресом выхода из Keycloak в `Location`, UI переходит туда.

## Состояние таблицы в URL

Вся выборка хранится в query-строке (`lib/bondSearchParams.ts`): ссылку можно сохранить, «Назад» работает.

| Параметр                   | Что                                  | По умолчанию |
| -------------------------- | ------------------------------------ | ------------ |
| `scope`                    | `all` / `local` / `foreign`          | `all`        |
| `page`                     | номер страницы с 1 (бэк считает с 0) | 1            |
| `size`                     | 25 / 50 / 100 / 200                  | 50           |
| `sort`                     | `ПОЛЕ:ASC\|DESC`                     | `PRICE:ASC`  |
| `priceMin`, `priceMax`     | цена в рублях                        | -            |
| `percentMin`, `percentMax` | цена в % от номинала                 | -            |
| `risk`                     | уровни риска через запятую           | все          |
| `ofz`                      | `any` / `only` / `exclude`           | `any`        |
| `coupon`                   | `any` / `fixed` / `floating`         | `any`        |

В URL пишутся только значения, отличные от умолчаний. Неизвестные значения при разборе заменяются умолчаниями.
Сортировка в UI - по одному полю; бэк поддерживает несколько.
